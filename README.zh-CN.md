# TimeTrap · 时间边界实验室

把你的网站放进几个平行时区，提前经历夏令时、跨年和闰日，再把操作和截图导出为能复现的测试。

## 在 Mac 上打开

第一次：安装 Node.js 22.13 或更新版本，在本目录打开终端执行：

```sh
npm ci
npx playwright install chromium
npm start
```

以后可以双击本目录的 `启动TimeTrap.command`，或再次执行 `npm start`。打开 http://127.0.0.1:4317 。关闭运行工具的终端或按 Control+C 即可停止。

## 第一次体验

1. 点击「启动一次时间实验」。等待三个真实浏览器截图出现。
2. 点击「+ 1 分钟」。纽约从 01:59 回到 01:00，而倒计时从 120 减少为 60。
3. 点击「案例档案」，执行任意案例，查看出错时区与 UTC 对照。
4. 返回「平行实验」，填写选择器 `#count`，预期文字填 `60`，点击「添加文字断言」。
5. 点击「导出复现包」，下载 ZIP，解压后打开 `report.html` 查看完整截图。所有原文件也在 `output/session/`。

FAIL 在案例页表示成功重现了历史错误；在你自己写的文字断言中表示网页未达到你的预期。没有断言的截图只是一份观察记录。

## 测试自己的页面

目标地址支持 localhost 与 HTTP(S)。起点必须带 UTC 偏移，例如 `2026-11-01T05:59:00Z`。同一个瞬间在各时区显示为不同的本地时间，这是正常现象。

「推进」会执行浏览器定时器；「跳转」和滑轨只改变时钟，不补跑错过的定时器。改变时区需要重新启动实验。操作通过元素选择器同步执行；截图点击后会放大。

需要登录的站点使用独立空白环境，不读取你平时浏览器中的账户。本版不提供登录状态导入。页面依赖服务器时间时，前端时间跳转可能对它没有影响。

## 真实验证范围

三个公开报告的复现与 UTC 对照、纽约春秋时钟变化、定时器、填表和点击、文字断言，以及导出的脚本实际执行，都在本地 Chromium 中验证。两个项目执行固定历史提交的原始函数；第三个重建报告中的日期处理用法。没有运行完整的上游应用，也没有发现新漏洞。

本地工具无需 AI API Key。对外站点仍需网络连接。服务器时间、真实服务端过期、证书和跨域框架不在本版覆盖范围。报告可能包含页面上的私人信息，分享前请检查。

源码和精确来源见 [案例说明](docs/CASES.md)。完整开发者说明见 [英文 README](README.md)。

## 动态界面（0.1.1）

黑白双栏首页包含三时区回拨预演：拖动滑轨可以精确观察纽约的 01:59 → 01:00。预演与下方真实浏览器实验相互独立。右上角可以暂停全部动效；系统要求减少动态效果时默认暂停。实验区域包含执行扫描、截图入场与键盘可操作的放大预览。
